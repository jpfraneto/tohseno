01 · The Shot

A complete world, not a diff.

One random ShotID survives every Evolution. Each integer Evolution is a complete source world, the app's CFBundleVersion, and one signed link in an immutable lineage.

Permanent

Stable identity

The slug, bundle ID, website, token, factory, and server may change. The 32-byte ShotID does not.

Exact

Known anatomy

The finite Apple Fascia declares identity, storage, privacy, continuity, provenance, and capabilities.

Owned

Signed history

Canonical records use deterministic bytes, SHA-256 commitments, and low-s P-256 signatures.

Portable

Factory freedom

The next complete Evolution may be created by any implementation that passes the same protocol law.

02 · Identity

The builder is durable. Keys and devices are replaceable.

TOHSENO keeps ownership, signing authority, recovery, and app-user identity deliberately separate.

  1. BuilderID

    A stable smart-account address that controls Shots. It is not a username, Apple ID, company account, or permanent key.

  2. Builder DeviceKey

    A hardware-backed P-256 key authorized for exact protocol actions. A lost key can be revoked without moving the Shot.

  3. Recovery Root

    An optional, separately secured Ethereum recovery authority. It never enters a generated application.

  4. InstallationKey

    An app-specific P-256 identity created by one app installation. It creates no universal cross-app user profile.

03 · Privacy

Private first. Public by signature.

A registry witnesses a Shot that already exists. It never receives the person's prompts, reference images, app data, usage, recovery material, or private continuity graph.

Private by default

  • intention and reference images
  • unpublished source and local app data
  • installation identities and continuity links
  • device inventory and recovery material

Explicit signed action

  • Evolution commitment and public head
  • controller and publication state
  • builder-selected public artifact URI
  • handle, appcoin, or App Store relation

04 · Replaceability

Nodes index. Builders own.

Anyone may relay a valid action. The messenger gains no ownership. No official app, node, factory, company, token, or website is recognized by the contracts.

Cryptography  →  this key signed this digest
Schema        →  this digest means this exact action
BuilderID     →  this key is authorized
Registry      →  the public transition is valid

05 · Conformance

Compatibility is a testable claim.

A deterministic verifier reproduces record bytes and commitments, checks P-256 authority and ordered lineage, inspects the Apple project and Fascia, and reports evidence for every judgment. It never asks an LLM whether an app conforms.
