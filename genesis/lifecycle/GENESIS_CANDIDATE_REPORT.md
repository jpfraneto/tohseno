# TOHSENO GENESIS candidate evidence

This report records only evidence that exists. **GENESIS 0.7.0 is a
protocol candidate, not the canonical shipped protocol.** It is not ready for a
prerelease: the physical-device Genesis lifecycle, real Shot, contract
deployment, and public witness remain incomplete. It is also not ready for
cleanup: that separate post-release acceptance state requires installing and
exercising the published prerelease, which does not yet exist.

[`GENESIS_CANDIDATE_REPORT.json`](GENESIS_CANDIDATE_REPORT.json). The exact
read-only P256VERIFY call input/result and the retained candidate network reads

  artifact checks, candidate-only bundle/keychain namespaces, sandboxed

  Secure Enclave action signing, deterministic calldata, private create-new
  artifacts, optional relay through only a named Foundry keystore or
  Ledger/Trezor, a distinct engine-enforced authorization for lazy
  BuilderAccount deployment, duplicate-key-strict receipts,
  transaction-by-hash envelope binding, retained identifiers after
  post-broadcast verification failures, and exact post-state checks. The
  default is signed preparation without broadcast.
- Non-upgradeable BuilderAccount, factory, ShotRegistry, and ShotRelations
  candidate contracts. They remain unaudited and undeployed.
- Exact candidate artifacts: descriptor-anchored staging and cleanup, atomic
  Darwin/Linux publication, complete manifests, dirty and clean provenance,
  normalized Genesis archives, isolated transactional candidate installation,
  and least-privilege prerelease workflows gated by both recorded prerelease
  readiness and explicit machine-readable authorization. Immediately before
  draft creation and again before publication, the workflow re-reads the exact
  live GitHub tag ref, peels a bounded annotated-tag chain, and requires the
  terminal commit to match the workflow event commit. An interrupted run may
  reuse only its commit-bound unpublished draft; the exact asset set is
  clobbered, downloaded, and compared before publication. A lost publish
  response converges only if the existing public prerelease is immutable and
  every tag, marker, and asset check still matches. Post-release cleanup
  readiness is tracked separately.
