App → Intent → App on your iPhone.

TOHSENO is an open-source local app factory. Describe a deliberately small app or change; your Mac builds, checks, signs, installs, and launches the result on your iPhone.

Install the Mac app

Download TOHSENO for Mac. The route stays unavailable until the exact Developer ID-signed, notarized, stapled DMG and its independently checked SHA-256 are published. Source support is not a download claim.

TOHSENO requires macOS 14 or newer and full Xcode. It does not require sudo, Node, npm, Bun, Homebrew, or a TOHSENO account. An iPhone is needed for phone installation, not for browsing existing apps or preparing local work.

One readiness instruction at a time

  1. Connect and trust the iPhone.
  2. Enable Developer Mode when iOS asks.
  3. Install Xcode and add an Apple Account for development signing.
  4. Choose an Apple Personal Team in Xcode when development signing requires it.
  5. Let TOHSENO verify a minimal build, install, launch, and cleanup.

The native app talks only to the loopback Local Workspace Service and gives one next action at a time. It never collects Apple credentials. A free Apple Personal Team is supported; Apple provisioning limits still apply. Installing or pairing the optional Companion is not a readiness or creation gate.

Create one deliberately small app

Open TOHSENO's native composer. Describe the app, optionally name it, and attach up to eight exact-byte PNG or JPEG references. If the name is blank, the implementation model chooses a concise product name inside the same implementation pass.

Advanced settings detect supported subscription-backed tools and allow a bounded custom executable or explicitly consented loopback model endpoint. Managed intelligence is optional: it shows a live server-priced range, privacy tier, and hard maximum before source is sent. Local/BYO work is never gated by TOHSENO subscription or creation balance.

The persistent local service runs one bounded implementation harness and, only for a concrete code or build defect, at most one focused repair. Source generation is not completion: TOHSENO builds, verifies, development-signs, installs, and launches the accepted app on the connected iPhone. If the phone is absent, the app waits and delivery resumes automatically when it is connected.

Use it, then describe the change

Open the app, write what should change, and press Evolve App. TOHSENO binds the exact currently accepted base automatically and follows the same build, verification, installation, and launch path. A stale base is refused rather than silently rebased.

The app and its TOHSENO record stay on your Mac

Visible app folders live under ~/Desktop/Tohseno and remain ordinary Git repositories. The app-local .tohseno directory is an integral metadata container, not a disposable cache and not blanket-gitignored. Its app marker, immutable evolution structure, and safe integrity material travel with the folder.

Exact intentions, inline private lineage, references, feedback, execution receipts, logs, and .tohseno/private remain individually gitignored because committing them could publish material explicitly marked private. Machine identity, service journals, pairing, and installed releases live separately under ~/.tohseno. Uninstall preserves both app folders and private state.

TOHSENO does not upload canonical Shot data. A selected local/BYO tool handles source under its provider settings. A configured loopback endpoint requires explicit consent. Managed work alone sends admitted source through TOHSENO to Bankr and the selected model provider after privacy and maximum approval; the server ledger records usage and money movements but not source or prompts.

The contract is active; the registry product is not built yet

Contract generation 0.8.0 is deployed on Robinhood Chain mainnet (chain ID 4663) and is the current client-trusted generation under a threshold-signed activation: BuilderAccountFactory at 0xb1bd208cd2af98e701f43d06aaa889d3a594df65 and ShotRegistry at 0x3fe6508ba2660bc575080024f402c192a2e035a0.

Activation identifies the exact contract instances trusted by the current client; it is not a human-audit or formal-verification claim. Repository evidence records an owner-waived pre-activation canary and release keys created on one Mac. It also does not mean people can publish apps today. Secure public BuilderAccount creation, registry RPC and transaction orchestration, publication receipts, source hosting, catalog discovery, and download are not implemented. No current TOHSENO workflow uploads an app repository to this contract.

The on-chain registry stores only Shot identity, controller, public-checkpoint head, checkpoint count, and nonce. It cannot store or serve source code by itself. A real downloadable registry requires a separate content-addressed source catalog plus verified on-chain receipts. Until those workflows exist, do not send transactions or funds to these addresses.

Which version is live?

The native Mac transition is implemented in source. It is not claimed public until the owner has signed, notarized, stapled, physically tested, uploaded, independently hashed, and activated the exact DMG. Until then the download route fails closed.
