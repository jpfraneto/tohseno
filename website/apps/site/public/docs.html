Begin with the intention

  1. Visit the home page and write or paste the intention.
  2. Add zero to eight reference images and press TAKE A SHOT.
  3. Run the one command shown on the Mac.
  4. Continue in local Studio with the exact prompt and ordered references already present.

The browser preserves the editable draft in IndexedDB. When encrypted handoff is available, it sends only temporary client-encrypted ciphertext. The Mac decrypts and validates locally. The website and relay do not create a Shot; the local engine does that after plan review.

If encrypted handoff is unavailable, download the private .tohseno-intent file, install normally, and run tohseno intent open <file>. The downloaded file is private and readable, not encrypted.

Generic installer alternative

{{INSTALL_COMMAND}}

TOHSENO 0.8.4 supports macOS 13 or newer. The generic one-line installer detects Apple Silicon or Intel, downloads the matching immutable GitHub release, verifies every checksum, installs transactionally under ~/.tohseno, adds tohseno to your shell path, and opens Studio.

You do not need a TOHSENO account. Xcode is required to build and install the native Apple expression. A local Codex or Claude Code installation and its own authenticated subscription are required when you take a real Shot.

Studio checks the Mac first

  1. Confirm macOS and the installed TOHSENO release.
  2. Check Xcode, Simulator, and Apple signing readiness.
  3. Detect installed Codex and Claude Code harnesses and their authentication state.
  4. Show where private Shot data and visible app folders will live.

Studio binds only to 127.0.0.1 and opens through an owner-only, one-time local session. If a prerequisite is missing, the onboarding screen gives the exact next action. Reopen it at any time with:

tohseno studio

TOHSENO checks the stable channel at most once per day and prints a short notice only when an update exists. Update or remove the installed program with:

tohseno update
tohseno uninstall

tohseno upgrade is an alias for update. Uninstall removes the program and its exact shell PATH entry while preserving Shots, identities, feedback, and other local data.

Take one deliberately small Shot

  1. For an imported intention, review the exact prompt, ordered references, and editable local name suggestion. Inline creation can still start here.
  2. Choose Codex or Claude Code, its model, and the subscription route showing $0.00.
  3. Review the proposed plan and Genome, then press APPROVE & OPEN TERMINAL.
  4. Watch Terminal or iTerm open with the exact command visibly preloaded.
  5. Press Enter yourself. TOHSENO never bypasses this human boundary.

The authentic harness then runs in its own terminal with normal input and output. TOHSENO does not scrape the conversation or insert permission-bypass flags.

Follow and review the result

tohseno shot follow <execution-id>
tohseno shot result <execution-id>

Studio and the CLI read the same durable lifecycle events. When the harness exits, TOHSENO independently compares the Git trees, verifies the accepted Evolution, and reports SHOT LANDED only when the resulting state passes its gates. Failed, cancelled, and unlanded sessions stay honestly labelled.

Every completion record includes timestamps, outcome, digests, changed files, a diff summary, validation evidence, available cost facts, and one next action.

Experience version 0001, then evolve it

tohseno feedback <app-name> --version 1 --text "What I experienced"
tohseno evolve <app-name>

Feedback attaches private experience to one exact accepted version. An Evolution changes the same coherent intention and preserves its stable identity, lineage, and repository; a different intention becomes a different Shot.

Choose Evolve a Shot in Studio to select the feedback, add a focused evolutionary intention and new references, then take the next Shot through the same visible human boundary.

Your canonical Shot stays on your Mac

Browser Drafts stay in IndexedDB. Explicit handoff temporarily sends only opaque ciphertext. Imported Local Pending Intentions, machine identity, and installed release state live under ~/.tohseno; uninstall preserves them. Visible Shot folders live under ~/Desktop/Tohseno, with private intention, feedback, reference, and execution material in gitignored .tohseno folders.

The relay cannot decrypt the handoff and deletes ciphertext after durable local import or seven-day expiry. Studio does not upload canonical Shot data. The selected coding harness can read the local intention and references after approval and handles them under that provider’s privacy, retention, and account settings.

Every Shot remains an independent Git repository. Removing the TOHSENO command does not remove its source or history.

On-chain status

Contract generation 0.8.0 is deployed on Robinhood Chain mainnet (chain ID 4663) as an inactive, untrusted candidate: BuilderAccountFactory at 0xb1bd208cd2af98e701f43d06aaa889d3a594df65 and ShotRegistry at 0x3fe6508ba2660bc575080024f402c192a2e035a0.

No TOHSENO release reads from or writes to these contracts, and activation is not authorized: it stays gated behind independent review, a production canary, and threshold activation. A defective candidate is abandoned, never repaired in place. Do not send anything to these addresses. The complete signed deployment evidence lives in the repository under contracts/deployments and contracts/audits.

Older installs could show a predicted on-chain BuilderID address through tohseno identity show. That prediction belongs to a retired contract generation, which will never be deployed, and it is not an address in the deployed generation: do not treat it as a durable public identity, proof of ownership, or a future deployment coordinate, and do not send anything to it.

Your local identity, Shots, feedback, and signed history remain valid and verifiable on your Mac. A future release will activate the finalized successor generation and its own public BuilderID path.

Coming from an older install

The installer preserves existing ~/.tohseno/apps data byte-for-byte. Nothing is migrated or deleted during installation.

tohseno migrate-legacy
tohseno verify <app-name>

The explicit migration copies each valid legacy app into the visible folder model and projects its frozen history without rewriting the original ledger. You can migrate every app or pass one app name.
