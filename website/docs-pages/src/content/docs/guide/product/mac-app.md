title: Tohseno for Mac
description: The native product surface over the one persistent local factory.
---

`Tohseno.app` is the primary consumer surface. It is a native SwiftUI application over the one existing Rust service and factory—not a second implementation of the build system.

## Navigation

The normal Mac destinations are:

- **Apps** — adopted and created apps, creation, evolution, build history, source, and phone delivery.
- **Registry** — Discover, private Following, private Updates, search, and verified public software.
- **Profile** — the person's bounded public Builder identity and private relationship state.
- **Settings** — readiness, coding route, paired devices, balance, and diagnostics.

When the library is empty, **Adopt Existing App** is first and **Create a First App** is second. There is no return of the deleted Studio dashboard or a mandatory blank prompt wall.

## One service underneath

The app authenticates to a loopback Local Workspace Service through a signed-app helper, one-use workspace challenge, and short-lived, per-instance, scoped session. The service owns command admission, journals, the factory lease, execution, status, and reconciliation. Closing the window does not redefine those records.

On first open, the app verifies and atomically installs the bundled universal factory release with rollback protection. The signed/notarized DMG, native app, CLI, service, and Companion payload are parts of one release, not independent updaters.

## Keyboard behavior

In a focused intention composer:

- **Return** sends.
- **Shift–Return** inserts a line.
- The send path has exactly-once guards.

Settings for creation are open by default so detected authenticated harnesses are visible. Discovery checks bounded known locations—standalone, Homebrew/global, Volta, npm-global, Bun, and installed NVM paths—without executing a user shell.

## Presence and recovery

The running product has a menu-bar item. Durable jobs survive a native window or app restart because the service journal, not SwiftUI memory, is authoritative. Retirement preserves source and accepted history; Diagnostics can show retired apps and restore one to the library without silently reinstalling it on a phone.

The CLI remains a recovery and automation surface. It does not create a second product model.
